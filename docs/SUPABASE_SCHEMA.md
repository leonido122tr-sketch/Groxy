# Соглашения Supabase для проекта Groxy

Этот документ фиксирует соглашения, чтобы приложение, RLS-политики и триггеры в Supabase оставались согласованными.

## Таблица `public.profiles`

- **Первичный ключ и колонка с id пользователя:** **`идентификатор`** (uuid, ссылка на `auth.users(id)` on delete cascade).
- **Не использовать** колонку с именем `id` в этой таблице — в проекте везде используется **`идентификатор`**.

### Русские имена колонок

Приложение обращается к таблице только по русским именам:

| Колонка            | Описание                          |
|--------------------|-----------------------------------|
| `идентификатор`    | PK, ссылка на auth.users(id)      |
| `отображаемое_имя` | Имя для отображения (форум и т.д.)|
| `электронная_почта`| Email                             |
| `аватар`           | Путь/URL аватара                  |
| `город`            | Город (опционально)               |
| `телефон`          | Телефон (опционально)             |
| `метаданные`       | JSON (опционально)                |
| `создано_в`        | timestamptz                       |
| `обновлено_в`      | timestamptz                       |

### RLS и триггеры

- Во всех **RLS-политиках** для `profiles` использовать **`идентификатор`**, например:  
  `auth.uid() = идентификатор` (в USING и WITH CHECK).
- В **триггерах** на `auth.users`, которые вставляют строку в `profiles`, указывать колонки с русскими именами, например:  
  `insert into public.profiles (идентификатор, электронная_почта, обновлено_в) values (new.id, new.email, now())`.

Так не будет расхождений между приложением и настройками в Supabase.
