# Сверка таблицы `public.profiles` с приложением

Используйте этот документ, чтобы убедиться, что структура таблицы в Supabase совпадает с тем, что ожидает приложение.

---

## 1. Что ожидает приложение (по коду и docs)

| Колонка в БД | Тип (ожидается) | Где используется в коде |
|--------------|-----------------|---------------------------|
| `идентификатор` | uuid, PK | register, profile/setup, forum, auth callback, RLS |
| `отображаемое_имя` | text, nullable | register, profile/setup, forum (автор), select/upsert |
| `электронная_почта` | text | register, profile/setup, auth callback |
| `аватар` | text, nullable | forum (автор), profile/setup select |
| `обновлено_в` | timestamptz | register, profile/setup upsert |

Опционально (по `docs/SUPABASE_SCHEMA.md`): `телефон`, `метаданные`, `создано_в`.

В регистрации приложение также передаёт **`display_name`** (латинское имя) на случай, если в БД есть колонка с таким именем вместо/вместе с `отображаемое_имя`.

---

## 2. Запрос для проверки колонок в Supabase

Выполните в **Supabase → SQL Editor**:

```sql
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'profiles'
ORDER BY ordinal_position;
```

Сравните результат с таблицей выше. Важно:

- Есть ли колонка **`отображаемое_имя`** (кириллица). Если её нет, запись из приложения в это поле не попадёт.
- Есть ли **`идентификатор`** как первичный ключ (не `id`). От этого зависят RLS и `onConflict: 'идентификатор'`.
- Есть ли **`display_name`**: приложение при регистрации пишет и туда, и в `отображаемое_имя`.

---

## 3. Если в БД только латинские имена

Если в таблице есть, например, `id`, `display_name`, `email`, но **нет** `идентификатор`, `отображаемое_имя`, `электронная_почта`:

- Либо приведите таблицу к схеме с русскими именами (добавьте/переименуйте колонки по `docs/SUPABASE_SCHEMA.md` и `docs/supabase_profiles.sql`).
- Либо измените приложение так, чтобы оно использовало только латинские имена колонок (`id`, `display_name`, `email`) и обновите RLS под `id`.

---

## 4. Краткий чеклист

- [ ] В `public.profiles` есть колонка `идентификатор` (uuid, PK).
- [ ] В `public.profiles` есть колонка `отображаемое_имя` (text, nullable).
- [ ] В `public.profiles` есть колонка `электронная_почта`.
- [ ] RLS: `profiles_insert` и `profiles_update` используют `auth.uid() = идентификатор`.
- [ ] После регистрации в консоли браузера нет сообщения «Ошибка записи профиля (profiles): …».

После сверки можно прислать вывод запроса из п. 2 и (при необходимости) текст ошибки из консоли.
